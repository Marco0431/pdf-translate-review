# 审查方法论（PDF 翻译逐字核对指南）

本指南解决一个核心问题：**如何确保译文里的每个公式、每句翻译都与原文一致**。

## 为什么必须用渲染图核对公式

PDF 文本层提取（`to_markdown` / `page.get_text`）对公式极不可靠：

| 现象 | 原因 | 后果 |
|---|---|---|
| 公式整块空白 | 公式是矢量/图片对象，无文本层 | 凭记忆补写必然出错 |
| 丢括号 | 大括号/矩阵括号常是独立绘制 | `J_i^{-T}(u_i+f_i)` 被读成 `J_i^{-T}u_i+f_i` |
| 丢上下标 | 上下标是单独文本块 | 下标错、`(I-η)` 与 `(1-η)` 分不清 |
| `1` 与 `I` 混淆 | 字形视觉近似 | 含义完全改变 |
| 乘积范围不明 | 括号丢失 | 无法判断 `(I-a)b - ac` 还是 `(I-a)(b-c)` |
| 上下标/分数误认 | 上下标位置窄、分数线细 | 加号结构被读成分数，或下标读成上标 |

**结论**：文本层只作为翻译的文字基准；**公式的精确结构必须用页面渲染图（800–1600 DPI 裁剪）逐字确认**。

---

## 核对流程

### 第 1 步：建立核对基准

1. 提取全文文本 → `out/paper.md`（文字基准）：`python scripts/extract_pdf.py paper.pdf --out out/`
2. 渲染每页 150 DPI 整页图 → `out/assets/raw/`（定位公式位置）。
3. 提取全部 `Fig.` 图注与表格标题，建立图片/表格清单。

### 第 2 步：定位公式

```bash
python scripts/zoom_formula.py paper.pdf --page 4 --list --kw "eta" "J" "D"
```

输出含 x/y 坐标的文本行。**同一行内多个片段 + 不同 y 坐标**常表示大括号、分数线或上下标结构，必须裁剪确认。

### 第 3 步：裁剪高清渲染

```bash
# 按页面比例裁剪（如第 4 页中部区域：x0,y0,x1,y1 取 0~1）
python scripts/zoom_formula.py paper.pdf --page 4 \
  --crop 0.02,0.30,0.55,0.35 --dpi 1200 --out eq12.png

# 或按绝对点坐标（先用 --list 拿到 bbox）
python scripts/zoom_formula.py paper.pdf --page 4 \
  --crop-abs 40,318,300,328 --dpi 1600 --out eq12_tight.png
```

用 Read 打开渲染图，**逐字符确认**：括号范围、上下标、`I` 与 `1`、乘法作用范围、加减号。

公式看不清时可用 OCR 辅助获取字符线索（结果仅作提示，不能当真值）：

```bash
python scripts/ocr_formula.py eq12.png --upscale 4
```

### 第 4 步：逐式比对

对照原文渲染图，逐式核对译文公式。重点核对：

- 右侧结构与括号范围：`J_i^{-T}u_i+f_i` 与 `J_i^{-T}(u_i+f_i)` 是不同式子；
- 乘积作用范围：`(I-a)(b-c)` 中的第一个因子是乘整个括号，还是只乘首项；
- 下标与上标：`η_f,1` 与 `η_f,2`、`k_stiff` 与 `k_stiff,i`、`D(q)` 与 `D(\dot q)`；
- **上下标 vs 分数**：确认字符位置与是否有分数线，并配合参数表交叉验证符号命名；
- **竖线是单还是双**：`|x|` 与 `\|x\|`（`\Vert`）是两种不同符号，渲染出的码位也不同（单竖线 U+2223 / 双竖线 U+2225）。范数类符号必须回到原文渲染图确认是几根竖线，不要凭"看起来是范数"就写单竖线；
- 编号：每个公式的 `\tag{N}` 与原文一致；多行矩阵共享编号时确认共享关系；原文没有的公式不补写。
- **原文渲染图与译文渲染结果对得上**：改完公式后要把交付 HTML 用无头浏览器打开，导出每条公式的**渲染后可见文本**，与原文渲染图逐字符比——**不要以"渲染器没报错"收尾**（陷阱清单第 21、22 条）。

### 第 5 步：图片-图注一致性核对（必做）

图错位是最常见的重大错误。根因是 **PDF 内嵌对象顺序 ≠ 论文图注编号**。必须：

1. 提取 PDF 全部 `Fig.` 图注（编号连续 1..M，含页码/栏位）：
   `python scripts/extract_figs_by_caption.py paper.pdf --list`
2. 列出译文全部"图 N"标题与引用的 `assets/figN.png`；
3. 逐一比对：**数量相等（译文图数 = 论文图数 M）、编号连续、图 N 标题语义与图注一致**；多栏、附录、跨页的图不要漏；
4. 用 Read 逐张目视确认图片内容，而不是只看文件名；
5. 检查图片在文档中的**出现顺序**与图注编号顺序一致；
6. 同一图片文件**不得两次引用**表示不同图（组合图需按边界拆成两幅）。

```bash
python scripts/check_img_order.py out.html --expected 1,2,3,4,5
python scripts/check_img_dims.py out.html --min-width 300
```

### 第 6 步：自动验证

```bash
python scripts/verify_translation.py translation.md \
  --max-eq 38 \
  --assets-dir assets \
  --expect-imgs 15 \
  --section "## 摘要" --section "# 精读" \
  --check-english \
  --key 'J_i^{-T}u_i + f_{\text{rob},i}'

node scripts/verify_katex_md.js translation.md
```

`verify_translation.py` 检查：编号齐全与异常重复、`$$`/`$` 配对、无 `\(` `\)` 残留、章节存在、图片引用一一对应、`\left`/`\right` 与环境配对（排除 `\rightarrow` 误报）、相邻括号组减号歧义提示（可用 `--no-ambiguity-check` 关闭）、成段英文残留。`verify_katex_md.js` 逐条渲染公式，报告真实语法错误。两者都必须通过。

### 第 7 步：翻译核对

逐段比对文本层与译文，重点检查：

- 数字 / 单位 / 参数：长度、质量、时间、力矩等数值与单位；
- 条件取值：多组实验参数的具体取值；
- 引文编号 `[n]`、作者名、专有名词（机器人型号、求解器、软件名）。

### 第 8 步：反复检查

修正后**重跑第 6 步与第 5 步**。若要求"反复检查"，至少三轮：初查 → 修正 → 复查 → 再修正 → 终查，每轮都重跑自动验证，直到 0 问题。

### 第 9 步：HTML 产出复查（若交付自包含 HTML）

```bash
python scripts/build_html.py translation.md out.html
python scripts/check_all_html.py out.html
python scripts/check_source_leaks.py out.html     # 源码级：未配对定界符 / 正文 LaTeX / 双反斜杠 / 正文上下标 / 标签切断公式 / 畸形 span / Markdown 残留 / KaTeX 报错 / 图字节重复
python scripts/headless_check.py out.html
```

确认：公式全部渲染（无残留 `$`）、公式编号与公式不重叠、所有图片为 base64 内嵌且可解码、无相对路径图片。

**还要确认读者看不到源代码**——这一项 Markdown 阶段查不出来，必须在 HTML 上查：

1. 可见文本里没有未配对的定界符、没有原始 LaTeX（`\xi`、`\frac`、`\|`）、没有 `\(` `\)`；
2. 没有**双反斜杠命令**（`\\bar`、`\\|`、`\\mathrm`、`\\frac`）——单个反斜杠被写成两个（矩阵 /
   数组 / `cases` 环境里的 `\\` 换行符除外，见陷阱清单第 21 条）；
3. 没有 Markdown 残留（`**粗体**`、`_斜体_`、段首 `> `）、没有正文里的 `_{…}` / `^{…}`；
4. 没有**被标签切开的公式**：相邻两个文本节点带边界标记拼起来再匹配一遍定界符，结果不应改变；
5. 没有**不可能成形的数学 span**（花括号 / 圆括号 / 方括号不配对、`\left` 无 `\right`）；
6. `<span class="katex-error">` 数量为 0（静态文件查标记；auto-render 文件用无头浏览器加载后再查）；
7. 没有两张图字节相同却挂着不同标签；
8. 没有外链、没有非内嵌图片。

**判"渲染了没有"必须按该页自己的 `renderMathInElement` 配置来**：只把配置里列出的定界符算作
会被处理；预渲染页面（无 `renderMathInElement`）任何定界符都不处理。

**"错误数为 0"不是验收条件，只是必要条件**。最后必须再走一遍**渲染目视比对**（第 4 步的
延伸）：用交付件自带的 KaTeX 把每条公式渲染出来，导出**渲染后的可见文本**与原文公式逐条比。
实战教训：一个页面报出 6 条公式、0 个渲染错误，而其中 5 条数学是错的（4 条双竖线范数变成单
竖线、1 条 `\mathrm` 变成字面量字母），只看错误数完全发现不了（陷阱清单第 21、22 条）。

## 公式与结构陷阱清单

1. **凭记忆补公式**：文本层空白时绝不可凭印象写，必须渲染原图。
2. **漏乘 / 多乘系数**：如阻尼项本身已是力矩，再乘一次速度即语义错误。
3. **漏转置或转置方向错**：工作空间控制律常含雅可比转置，正/逆要看清。
4. **括号范围歧义**：`(I-a)b - ac`（仅首项被乘）与 `(I-a)(b-c)`（整体被乘）LaTeX 语法都合法、`\left`/`\right` 都配对，纯结构校验查不出。**做法**：放大页面图确认"减号两侧各被谁相乘"；再用下游推导式反推——把两种结构分别代入后续推导，能得到原文下一式的才是正确结构；若公式与相邻推导注释矛盾，必有一错。修复时同步改正文、精读、HTML 内嵌公式源三处。
5. **`1` 与 `I`**：柔顺度等说明文字可能用 `1-η`，公式里却用 `I-η`；两处都按原文保留，必要时加注释说明。
6. **编号拆子式**：原文一个编号下的多行式子不要拆成 `12a/12b` 之类；**若原文自身就用子编号**（如 `(28a)`–`(28d)`、`(42a)/(42b)`、`(57a)`–`(57g)`、`(60a)`–`(60d)`），必须照抄，不要"合并"成 `(28)`。**多行共享一个编号时，编号只在末行出现一次**——每行都写 `\tag{N}` 会让读者看到同一编号重复渲染（实战中出现过 4 组）。统计编号时，`\\tag\{(\d+)\}` 抓不到写在 `\text{(28a)}` 里的子编号，必须同时扫 `\text{\(…\)}`，否则会误判"原文有、译文缺"。
7. **行内公式分隔符**：译文统一用 `$...$`，不用 `\(...\)`。这条不只是 Markdown 规范——**产出 HTML 后，页面自己的 `renderMathInElement` 若只配置了 `$$`/`$`，写了 `\(...\)` 的内容会原样显示为源码**。实战中 7 份 HTML 共 1110 处行内公式栽在这里。两种正确改法：把定界符配置补上 `\(`/`\[`（一行改动、不动正文），或把正文全量换成 `$...$`。**不要**引入只把 `\(`→`(` 的"修复"——那会留下 `(\xi_{p_1}^O, ... \mathbb{R}^3)` 这种花括号残缺的可见源码。
8. **原文笔误**：忠实保留 + `> 注释`，不"善意修正"。
9. **按内嵌对象顺序取图**：必须按 `Fig. N` 图注定位，并逐张目视核对。
10. **图片顺序与编号不一致**：正文先引用小编号、后引用大编号时，图片摆放顺序应大致随编号；同一文件重复引用表示两幅不同图（组合图未拆）也会造成错位。
11. **上下标 / 分数识别错误**：放大观察字符位置与分数线，配合参数表交叉验证符号命名。
12. **补写原文没有的公式**：原文只给出部分方程时，不得自行补全未出现的矩阵或方程；确有补充必须加"译者补充"注释。
13. **跨页公式组遗漏**：多式共用一个编号的公式组可能跨页（编号在末式）。判定"原文没有"之前，必须把编号页**及其前一页的两栏**都渲染核对，否则容易误删真实公式。
14. **只提及表格未转译**：正文写"见表 X"但没有表格内容，视为未完成；提取全部表格标题 → 渲染核对 → 完整转译。
15. **扫描脚本误报**：统计 `\left`/`\right` 时，`\rightarrow` 含子串 `right`，普通字符串计数会产生大量假阳性，必须用 `\\right(?!arrow)` / `\\left(?!arrow)` 负向断言；配对检查应**逐公式块**（`$$...$$`）而非整篇或逐行，因为合法 LaTeX 允许 `\left(...\right)` 跨行。
16. **按"以为会渲染"判断渲染**：最常见、也最贵的误判。判某段公式是否会被渲染，必须看**该页自己的渲染配置**，不能看"源码里写了 LaTeX"。预渲染页面（只有 `katex-html` / `annotation`，没有 `renderMathInElement`）**什么都**不渲染；auto-render 页面只渲染它 `delimiters` 里列出的定界符。用这套规则统计，才不会把"1110 处未渲染"报成"0 泄漏"。
17. **交付件里的 Markdown 残留**：`**粗体**`、`_斜体_`、段首的 `> ` 引用记号。Markdown 转 HTML 若有段落未被解析，读者看到的就是星号和下划线。实战中 9 份 HTML 共 590 处。**检测要在"读者可见文本"上做**（跳过 `<script>`/`<style>`/`<pre>`/`<code>` 与 KaTeX 子树），否则会命中内嵌 JS 与 base64 里的字符串。
18. **KaTeX 解析失败回退**：公式语法错误时 KaTeX 不报错、而是吐出 `<span class="katex-error">` 把**源码染红**显示。典型成因是 `\frac{分子} 分母}` 少一个花括号。必须显式检查 `class="katex-error"` 数量为 0：静态文件查标记，auto-render 文件还要用无头浏览器加载后查运行时结果。
19. **同一个字节的图被当成两张不同图**：把图片按字节哈希两两比对，能直接抓出"标注为公式的图其实是某张论文图"。实战中 Ergo 的「公式 10 / 公式 12」与「图 4 / 图 5」字节完全相同，等于这两条公式从未显示。发现后要**回到原文 PDF 裁出真公式替换**，只删重复那张会把公式一起删掉。
20. **定界符与公式体被块级标签拆开**：`<p>$$</p><p>公式</p><p>$$</p>` 这种排版，auto-render 只在**单个文本节点内**匹配定界符，跨元素一定不匹配。显示公式必须写成同一个 `<p>$$…$$</p>`。同理，**公式被 `<span>` 等行内标签切断**时（一段公式落在两个文本节点里）任何客户端渲染器都救不了，此时把源码转成可读 Unicode 记法（`\xi_{p}^O` → `ξ_p^O`、`\frac{a}{b}` → `(a)/(b)`）比强行注入渲染器更可靠。
21. **双反斜杠陷阱（渲染不报错、数学是错的）**：把 `\|\bar{v}_L\|` 写成 `$\\|\\bar{v}_L\\|$`（每个反斜杠都多了一个）时，KaTeX **不报任何错误**：`\\` 按换行命令处理、`|` 按单竖线处理、`\\bar` 退化成字面量字母 `bar`。读者看到的是"换行 + 单竖线 + barv_L + 单竖线"，而原文印的是双竖线范数 `∥v̄_L∥`。实战中一个页面 6 条公式、0 个渲染错误，其中 5 条的数学是错的（4 条范数变单竖线、1 条 `x_{\mathrm{sym,th}}` 变 `xmathrmsym,th`）。**同类退化**：`\mathrm`、`\left`、`\frac`、`\bar`、`\hat`、`\text` 被多写一个反斜杠后命令名都会变成字面量字母。**检查方法**：把每条公式的**渲染后可见文本**（移除隐藏的 `.katex-mathml` 副本）与原文逐字符比，并统计竖线字符的**码位**（单竖线 U+2223 / 双竖线 U+2225）。**根因**：这段字符串要穿过 Shell → Python → HTML/JS 多层转义，任何一层多写一个 `\` 都会静默出错；**所以写入后必须读回文件用 `repr()` 按字符确认每一处改动的公式**。
22. **"渲染器没报错"被当成"渲染正确"**：这是 21 的直接后果，也是本次最贵的误判模式。渲染器"没报错"只说明它**接受**了这段 TeX，不说明它**排出的数学**和你想要的一致。所以核对公式要**两件事都做**：(a) 检查渲染错误数为 0（`class="katex-error"`）；(b) **目视比对渲染结果与原文渲染图**。只做 (a) 等于没查。实战：无头浏览器报告"katexSpans 6、errors 0"，而实际排出来的是 4 条单竖线范数 + 1 条字面量 `mathrm`。同时注意**渲染环境必须与被检页面一致**：用页面自带的 KaTeX bundle（版本要一致，实战是 0.18.1）渲染，而不是别的版本或别的排版引擎。
23. **把检查器的盲区当成覆盖率**：旧版 `check_source_leaks.py` 在配了 `$` 的页面上把 `$…$` **整段遮掉**再数剩下的源码，于是"公式体里写错了什么"永远查不到（第 21 项必然漏报）；它还把可见文本**跨标签直接拼接**再匹配定界符，拼接本身抹平了标签边界（第 20 项必然漏报）。结果它对两份确有缺陷的交付件都报"OK"。**规矩**：① 判"是否渲染"要按页面自己的 `delimiters` 逐**文本节点**匹配定界符，不要整段遮罩、不要跨标签拼接；② 定界符匹配后要**读公式体本身**做体检（括号是否配对、有没有双反斜杠、有没有被截断）；③ **改完检查器必须拿"已知有缺陷的旧版本"回归**——若新旧版本对同一份坏文件都报通过，说明新检查项没生效。

## 原文笔误的处理规范

1. **公式本体**：忠实保留原文写法；
2. **加注释**：在公式下方用 `> 注释：原文此处…` 说明疑似笔误及判断依据；
3. **不擅自改公式**：宁可保留原文笔误加注释，也不"修成自认为正确的形式"。

## 附录：可选 PDF 输出方案

Markdown 交付后若需生成 PDF：

### 方案 A：KaTeX + 无头浏览器打印（推荐，公式排版最好）

1. 用本仓库流水线产出 HTML：`python scripts/build_html.py translation.md out.html`
2. 用 Playwright/Puppeteer 的无头浏览器 `page.pdf({ format: 'A4', printBackground: true })` 打印；
3. HTML 里需设置中文字体（如 `Microsoft YaHei`），否则中文可能缺字。

### 方案 B：第三方 PDF skill / pandoc

用 `minimax-pdf` skill 的 REFORMAT 管道（其 matplotlib mathtext **不支持** `\boldsymbol`/`\boxed`/`align` 等复杂 LaTeX，且需注入中文字体），或用 `pandoc --katex` 转 HTML 后打印。公式复杂的论文优先方案 A。

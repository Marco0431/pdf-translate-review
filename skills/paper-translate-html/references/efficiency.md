# 质量优先的 token 与耗时优化

优化目标是去除重复传输和重复劳动。忠实性、段落覆盖、全文上下文及其证据、术语消歧、对照校对、图表核对和最终渲染验收保持不变。不以摘要替代原文，不降低模型能力来换速度，不抽样冒充全文校对。

## 已实现

- 默认 flow 接管请求编排和状态落盘，避免代理反复手工拼装材料。完整来源先覆盖再初译；只有有问题的段落重译，有风险证据的段落追加第二轮校对。修正后的最终全文校对保留。

- packet 默认将发给模型的 JSON 紧凑序列化；原文、上下文、图表占位符、术语、证据和检查内容不变。`--pretty` 仅供调试，解码后内容相同。
- 翻译校对提示的检查清单仅在响应契约中保留一份，不再重复发送另一个相同字段。
- `plan` 把相邻完整源单元组批，共享一次上下文、证据与输出契约；每个 ID 仍单独翻译和校对。合并后内部邻段直接成为当前批的源文，不丢掉语境。
- request_sha256 标识实际 messages；可用于识别完全相同请求。它不是供应商的缓存承诺，也不会自动调用 API 或将旧响应认定为合格。
- 已有块缓存仍核验 PDF、配置、上下文、术语及内容哈希；最终校对仍绑定当前全篇译文。不能将旧审校套到变更后的译文上。

```powershell
python scripts/translation_workbench.py plan --stage draft --document work/document.json --max-input-bytes 24000 --max-units 8 --out work/draft-plan.json
python scripts/translation_workbench.py plan --stage review --document work/document.json --translations work/translations.json --max-input-bytes 24000 --max-units 8 --out work/translation-review-plan.json
```

数值是调用示例，应按实际模型的上下文能力和文段密度调整。max-input-bytes 是消息正文 UTF-8 字节上限，不是 token 预算；还必须用供应商 tokenizer/usage 预留协议和输出空间，不能按字符数假定一定装得下。单元与完整上下文无法装入时 plan 报错，不静默截断；提高预算或重新整理来源单元并保留证据。

plan 中每个 packets 项是一个待执行请求，含 ids/messages/request_sha256/metrics。逐批或在可用配额内有界执行，响应按原始 ID 顺序汇总。默认不自动增加并发；需要吞吐量时先使用 2 个独立论文任务或不互相修改术语/上下文的冻结批次，根据 429/超时降低并发。同篇缓存仍为单写入者。校对任务只在其输入译文冻结后开始，归档需排在验收后。

## 工作流节省

1. 提取、图像渲染和术语消歧做一次并缓存；没有变化的来源不反复读取进模型。
2. 先跑便宜的结构检查，修复缺段/占位符错误再交给模型校对；结构正确仍必须语义校对。
3. 只针对有问题的块重译；改动后重新生成终版校对记录，不能以局部缓存替代跨段衔接检查。
4. 中文已自然且首轮校对通过时跳过可选润色；没有改动不空跑相同检查。明确有疑点时优先追加核对，不受速度目标限制。
5. 翻译默认不生成论文精读或学术评价，避免与 paper-reading 重复处理。

metrics 只报告消息正文字符数、UTF-8 字节数和请求数。真实 token、缓存命中、费用与耗时以提供方 usage/计时为准；不将字节减少率冒充 token 减少率，不保证每个模型压缩率相同。紧凑 JSON 的损失为零可通过解码相等验证，批处理后的真实翻译表现仍需原译对照，不能预先宣称语义质量已得到证明。

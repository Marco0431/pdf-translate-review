# Zotero 去重、附件与恢复

仅当用户要求“翻译并归档/挂到 Zotero”或既有授权涵盖本任务时执行写入；这已是授权，不额外逐项确认。只要求翻译时完成本地结果即可。

## 发现连接与确定目的地

先搜索已安装的 Zotero 工具，读取实际 schema 与支持操作；不要假设工具一定叫 `write_item` 或支持 `action=import`。没有 MCP 时，可使用已配置且授权的 API 或本地连接；本地 API 能否写入取决于已安装版本和连接能力，不能从网站文档推断本机已经支持。

记录库类型、库 ID、集合 key。个人库与群组库互不混用；有明确集合时沿用。未指定分类则优先已有相关集合，若无法合理确定就留待归类并报告，不自动批量创建主题分类。连接不可用时保留本地文件和 `archive_pending`，不因归档问题阻断其他翻译。

## 查重与元数据

按 DOI（移除 URL 前缀）、arXiv 基础 ID（另存版本）、其他稳定标识符查重；只有缺标识符时才用规范化标题加作者/年份。检索命中仅是候选，需回读字段确认。一个作品的多个预印本版本可以共用父条目并保留版本明确的附件；正式发表版不能盲目覆盖预印本的书目信息。

匹配多个候选时不自动合并/删除，保存候选 keys，归档置 pending。找不到条目时使用实际类型模板创建；期刊论文不一律填 preprint。缺作者、日期、DOI 等应留空或待补，不让模型编造。

只补充确有来源的字段，保留用户原有标签、笔记和集合成员关系。添加集合是合并成员关系，不以新列表清空旧分类。

## 归档账本与操作顺序

先在工作目录落盘 `archive.json`，包含：

```json
{
  "schema_version": 1,
  "status": "archive_pending",
  "library": {"type": "user", "id": null},
  "parent_item_key": null,
  "collection_keys": [],
  "source_sha256": null,
  "artifacts": [],
  "operations": []
}
```

artifact 记录实际文件、角色（source_pdf/translation_html）、语言、SHA-256、字节数、attachment_key、verified。operation 记录操作 ID、动作、状态（planned/confirmed/unknown/failed）和回执，不保存密钥。

1. 仅将本地 `ready` 译文纳入正式归档。草稿需要用户明确要求，附件标题标注“待复核”。
2. 回读已匹配或新建的父条目，立即保存 parent key。
3. 获取其全部子附件，按角色、语言、源 PDF 版本与内容哈希判断是否已存在；同一 HTML 哈希直接复用。父条目已存在不代表附件也存在。
4. 缺 PDF 时导入 PDF，随后导入完整的自包含 HTML；HTML 应为文件附件（`text/html`），不能用指向工作目录的 URL 冒充导入。已有不同内容的译文默认新建带版本标识的附件，只有明确更新目标时才替换对应附件。
5. 每个成功动作后保存 key/回执。导入超时属于结果未知，先回读子附件与账本核对再决定重试；不要一超时就重复 create。无法确认则留 pending。
6. 添加已有目标集合，最后回读父条目、附件的父子关系、文件名/MIME/字节数或服务端哈希，以及集合成员关系。能下载时下载核对内容哈希；不能取回内容时记录验证范围，不能声称字节级一致。
7. 元数据与附件确认到达目标库、分类核对完成后标 `archived`。仅本地导入成功不代表其他设备同步完成，跨设备同步应独立说明。

## API 与本地文件的边界

优先通过连接器支持的导入/更新完成文件与元数据登记。直接调用 Web API 时，使用版本前置条件处理并发更新；无版本的创建可使用稳定写入 token，重试前仍要回读。HTTP 200 的批量响应还要逐项检查失败结果。

API 文件上传遵循授权、传输、登记流程；现有文件使用原 MD5 作更新前置条件，SHA-256 用于本地内容身份，两者不要混用。出现 412 时重新读取当前状态后判定，不直接覆盖。实现细节按下面官方文档与实际连接能力检查。

旧 `sync_zotero.py` 会覆盖目标目录中的**所有 HTML**，不能用于无人值守默认更新。不得直接编辑 Zotero SQLite 数据库。若用户明确指定修复一个本地附件，先回读确认 key 与精确文件路径，备份后仅替换该文件，并通过 Zotero 确认更新；普通磁盘复制不等于服务端登记或同步。

官方依据（2026-09-22 核对）：[写入与版本控制](https://www.zotero.org/support/dev/web_api/v3/write_requests)、[附件上传](https://www.zotero.org/support/dev/web_api/v3/file_upload)、[本地 API 能力](https://www.zotero.org/support/dev/web_api/v3/local_api)。
